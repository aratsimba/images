#### 3.3 Key Schema Decisions

| Decision | Implementation |
|----------|---------------|
| Multi-tenancy | org_id FK on every table; enforced at middleware + query layer |
| Primary Keys | UUID v4 via gen_random_uuid() — no sequential guessing |
| Soft Deletes | status enum or is_active boolean; no hard deletes |
| Timestamps | created_at + updated_at with DEFAULT NOW() on all tables |
| Recurrence | RFC 5545 RRULE stored as VARCHAR; expanded at app layer via rrule.js |
| Visibility | ENUM('public','members_only','leaders_only') on events table |
| Indexes | 8 targeted indexes including partial index on is_recurring = true |

#### 3.4 SQL DDL (Key Tables)

```sql
-- Multi-tenant root
CREATE TABLE organizations (
    org_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    denomination VARCHAR(100),
    timezone VARCHAR(50) NOT NULL DEFAULT 'America/New_York',
    logo_url TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Events (core calendar entity)
CREATE TABLE events (
    event_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    org_id UUID NOT NULL REFERENCES organizations(org_id),
    title VARCHAR(255) NOT NULL,
    description TEXT,
    category_id UUID REFERENCES event_categories(category_id),
    campus_id UUID REFERENCES campuses(campus_id),
    room_id UUID REFERENCES rooms(room_id),
    start_datetime TIMESTAMPTZ NOT NULL,
    end_datetime TIMESTAMPTZ NOT NULL,
    is_recurring BOOLEAN NOT NULL DEFAULT false,
    recurrence_rule VARCHAR(500),        -- RFC 5545 RRULE
    recurrence_end_date DATE,
    visibility VARCHAR(20) NOT NULL DEFAULT 'public'
        CHECK (visibility IN ('public','members_only','leaders_only')),
    status VARCHAR(20) NOT NULL DEFAULT 'active'
        CHECK (status IN ('draft','active','cancelled','completed')),
    max_capacity INTEGER,
    requires_rsvp BOOLEAN NOT NULL DEFAULT false,
    childcare_available BOOLEAN NOT NULL DEFAULT false,
    livestream_url TEXT,
    contact_member_id UUID REFERENCES members(member_id),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Volunteer assignments (scheduling per event)
CREATE TABLE volunteer_assignments (
    assignment_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    org_id UUID NOT NULL REFERENCES organizations(org_id),
    event_id UUID NOT NULL REFERENCES events(event_id),
    role_id UUID NOT NULL REFERENCES volunteer_roles(role_id),
    member_id UUID REFERENCES members(member_id),
    status VARCHAR(20) NOT NULL DEFAULT 'assigned'
        CHECK (status IN ('assigned','confirmed','declined','swapped','open')),
    assigned_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    confirmed_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Indexes
CREATE INDEX idx_events_org_date ON events(org_id, start_datetime);
CREATE INDEX idx_events_category ON events(org_id, category_id);
CREATE INDEX idx_events_campus ON events(org_id, campus_id);
CREATE INDEX idx_events_recurring ON events(org_id, recurrence_end_date)
    WHERE is_recurring = true;
CREATE INDEX idx_registrations_event ON event_registrations(event_id, status);
CREATE INDEX idx_liturgical_season_dates ON liturgical_seasons(org_id, start_date, end_date);
CREATE INDEX idx_volunteer_event ON volunteer_assignments(event_id, role_id);
CREATE INDEX idx_scripture_date ON scripture_readings(org_id, reading_date);

```

### 4.7 Authentication Flow

Registration/Login → {access_token (15min), refresh_token (7d)}
         │
         ▼
API Request + Bearer access_token
         │
         ├── Valid → Process request
         │
         └── Expired (401) → POST /refresh with refresh_token
                                    │
                                    ├── Valid → New token pair
                                    └── Expired → Force re-login

#### 4.8 RBAC Middleware Chain

Request → rateLimiter(tier) → authenticate(jwt) → authorize(roles[]) → validate(schema) → handler

### 7. Security Design

| Control | Implementation |
|---------|---------------|
| Transport | TLS 1.3 (all traffic) |
| Encryption at rest | AES-256 (RDS + S3) |
| Password hashing | bcrypt, cost factor 12 |
| Token management | JWT RS256, 15-min access / 7-day refresh |
| Multi-tenancy | org_id extracted from JWT, applied to ALL queries |
| Input validation | Zod schemas on every endpoint |
| SQL injection | Prisma parameterized queries (no raw SQL) |
| XSS | DOMPurify on user-generated content |
| CSRF | SameSite cookies + custom header validation |
| Rate limiting | Redis sliding window, per-role tiers |
| CORS | Strict origin allowlist |
| Headers | Helmet.js (HSTS, X-Frame-Options, CSP) |
| Audit logging | All admin/pastor actions logged with actor + timestamp |
